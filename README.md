# Yapay Zeka Destekli Web Quiz ("Son Kararım")

A category-based quiz web application in the style of "Who Wants to Be a Millionaire" (the app's name, "Son Kararım", means "My Final Answer"). The backend runs on Node.js / Express and data is stored in MongoDB. Questions are generated by a language model (`google/flan-t5-base`) through the Hugging Face Inference API. If the API can't be reached, the quota is exhausted, or the response isn't in the expected JSON format, the ready-made questions in `public/questions.json` are used. The UI is in Turkish; an English language option is also available.

## Features

- **Registration and login**: Users register with a username, email and password. Passwords are hashed with bcrypt. On login, both a server-side session (`express-session`, stored in MongoDB) and a JWT valid for 1 day are created; the JWT is written to `localStorage` in the browser.
- **Roles**: Student (`student`) or teacher (`teacher`). A user who registers as a teacher is automatically given an 8-character teacher code. The "Soru Havuzu" ("Question Pool") button on the home page is shown only to teachers.
- **Categories** (`katagori.html`): Teknoloji (Technology), Sinema (Cinema), Müzik (Music), Dil Bilgisi (Grammar), Araba (Cars), Kültür (Culture), plus the Kapışma (Showdown) and Zaman (Time) modes. The fallback question file has 10 questions per category.
- **AI question generation**: `POST /api/questions/generate` requests 10 Turkish questions with 4 options each for the selected category and validates the format of the response.
- **Quiz screen** (`chat.html`):
  - 20 seconds per question; if time runs out, the answer counts as wrong.
  - Correct/wrong sound effects (`image/correct.mp3`, `image/wrong.mp3`).
  - A/B/C/D keyboard shortcuts.
  - Lifelines: 50:50 hides two wrong options. The Audience and Phone lifelines currently only show a "(Demo)" notice.
  - Scoring: If all 10 questions are answered correctly, 10 points are earned and the score is saved with `POST /api/score`; otherwise the score is 0.
- **Settings**: Sound on/off, dark mode, Turkish/English language selection. Preferences are stored in `localStorage`.
- **Profile picture**: An image uploaded from the browser is saved to `localStorage` as base64 (it isn't sent to the server).
- **Leaderboard API**: `GET /api/leaderboard` sums users' scores per category and sorts by total score.

## Technology

- **Backend**: Node.js, Express 4, Mongoose 7, express-session + connect-mongo, jsonwebtoken, bcryptjs, dotenv, node-fetch
- **Frontend**: Static HTML/CSS and a single `script.js` file (vanilla JavaScript)
- **Database**: MongoDB
- **AI**: Hugging Face Inference API, `google/flan-t5-base` model

## Requirements

- Node.js and npm
- A running MongoDB server (local or MongoDB Atlas). Both application data and sessions are stored there.
- A Hugging Face access token for AI question generation (optional; without it, the fallback questions are used)

## Setup and running

```bash
cd proje2
cp .env.example .env       # then fill in the values
npm install
npm start                  # node server.js
```

By default the server starts at `http://localhost:3000` (can be changed with the `PORT` variable). `node_modules` isn't kept in the repository; it is installed with `npm install`. Because `require('node-fetch')` doesn't work with version 3.x, `package.json` specifies `node-fetch` 2.x (`^2.7.0`).

## Configuration

The following variables are read from `proje2/.env`. The file isn't committed to git (`.gitignore`); use `proje2/.env.example` as a template:

| Variable | Description |
|---|---|
| `MONGODB_URI` | MongoDB connection URI (for Mongoose and the session store) |
| `SESSION_SECRET` | `express-session` signing secret |
| `JWT_SECRET` | JWT signing secret |
| `PORT` | Server port (default 3000) |
| `HUGGING_FACE_TOKEN` | Hugging Face Inference API token |
| `GOOGLE_ID`, `GOOGLE_SECRET` | Present in `.env.example` but not used by `server.js` |

When `NODE_ENV=production`, the session cookie is marked `secure`; HTTPS is required in that case.

> **Security warning:** The `.env` file was committed to git at one point and is still in the git history. The database URI, secrets and tokens in that file should be considered public and must be rotated.

## API endpoints

| Method | Path | Authentication | Description |
|---|---|---|---|
| POST | `/api/register` | none | `fullname, username, email, password, role, teacherCode` |
| POST | `/api/login` | none | `username, password`; opens a session and returns `{ token }` |
| GET | `/api/user` | session cookie | The logged-in user's details (excluding password) |
| POST | `/api/score` | `Authorization: Bearer <token>` | Saves `{ kategori, puan }` |
| GET | `/api/leaderboard` | none | Per-user category and total scores |
| POST | `/api/questions/add` | Bearer token | Adds `{ question, options, correct, category }` |
| GET | `/api/questions/user` | Bearer token | Questions added by the user |
| POST | `/api/questions/generate` | Bearer token | Generates 10 questions for `{ kategori }` (returns fallback questions on error) |

Question format (for both AI output and `questions.json`):

```json
{ "soru": "Soru metni", "secenekler": ["A", "B", "C", "D"], "dogru": "B" }
```

## Known gaps

- `leaderboard.html` currently doesn't fetch data from the API; it shows sample data hard-coded into the page (the `/api/leaderboard` call is commented out).
- The `soruhavuzu.html` form saves questions via `POST /api/questions/add`, but the list section still shows a fixed sample question (`/api/questions/user` isn't called).
- The Google and Facebook buttons on the login screen redirect to `/auth/google` and `/auth/facebook`, but these routes aren't defined. The `passport` packages are in the dependencies but unused.
- The `highscores.html` link on the home page and the `/settings.html` route on the server point to files that aren't in the repository.
- The Audience and Phone lifelines aren't functional (demo).
- The flags folder has de, es, fr and zh files, but `script.js` only contains `tr` and `en` translations.
- If the server can't find a JSON array with exactly 10 valid questions in the model response, it falls back to the fallback questions. Since `flan-t5-base` is a small model, this fallback may happen often.
- The repository has no license file; no license is specified.
